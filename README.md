# DigiPhant — a three-person elephant puppet for Unity

DigiPhant is a digital elephant that three people perform together through one laptop webcam.
Python (MediaPipe) tracks bodies, faces and hands on your own computer and streams the measurements
to Unity over localhost. Nothing is sent online.

| Performer | Camera position | Role | What they control |
|---|---|---|---|
| **P1** | Left third | Upper body | Walking (left hand up or down), turning, head and tail (tilt shoulders), legs (raise either hand), trunk curl (right hand height), ears (hands apart or together), drinking (both hands up for 2 s at the water pool) |
| **P2** | Middle third | Face | Rearing up (open mouth), picking the apple (right-eye wink) or the banana (left-eye wink) |
| **P3** | Right third | Hands | Grabbing and carrying the log (fists), sitting on the log (✌️) |

Demo video: <https://drive.google.com/drive/folders/1XvavueuYdmjC1N-thfG7S0AxbH4DiyA7>

third-party packages are left out on purpose. You restore them in step 3.

## 2. Requirements

### Technical

| Item | Requirement | Tested with |
|---|---|---|
| Unity | **6000.6.3f1** with URP 17.6; install it through Unity Hub | 6000.6.3f1 |
| Computer | macOS (Apple Silicon) or Windows. The Windows paths are coded but **untested** | macOS 26.5, Apple Silicon |
| Python | **3.14**, used only through `DigiPhantStarter/Tracking/.venv` | 3.14.7 |
| Python packages | `mediapipe==0.10.35`, `opencv-contrib-python==4.14.0.94` (from the starter's `requirements.txt`) | same |
| Git | Any recent version | — |
| Webcam | Built-in or USB webcam, camera index 0 by default | MacBook built-in camera |
| Disk | About 1 GB for the project and Python packages, plus Unity's `Library/` cache after first import | — |

### Physical

- **One webcam, three people seated side by side**, all facing the camera. The preview is split into three
  equal vertical strips (**Fixed zones**), and each person must stay inside their own strip:
  - **left strip:** P1 (Upper body);
  - **middle strip:** P2 (Face);
  - **right strip:** P3 (Hands).
- **Each person's head, both shoulders and both hands must be in the frame,** including when hands are
  raised above the head. P3 raises both hands to claim the Hands role, and P1 raises both to drink.
- **P2 sits closest to the camera, or the camera is at P2's eye level.** The wink and mouth detectors
  need a clear, front-lit view of P2's eyes and mouth. Glasses glare and side lighting make winks harder to
  detect.
- **Light the faces from the front and keep the background plain.** Keep bystanders out of the frame.
- **Don't swap seats during a performance.** Each person's number is the strip they sit in.

## 3. Installation (fresh checkout)

Run every command from the repository root (the folder that contains `Assets/`).

### 3.1 Clone this repository
```sh
git clone <YOUR_REPO_URL> DigiPhant
cd DigiPhant
```

### 3.2 Clone the course starter at the pinned commit
```sh
git clone https://github.com/kommanderpi/studentstarter.git DigiPhantStarter
git -C DigiPhantStarter checkout 4e6dab5271c618d1c0bfb2022c41c0d37cd8d69f
```

### 3.3 Restore the elephant assets
This step checks every file's checksum. It refuses to overwrite assets that differ.
```sh
python3 tools/restore_shared_assets.py
```

### 3.4 Create the Python environment
macOS:
```sh
python3.14 -m venv DigiPhantStarter/Tracking/.venv
DigiPhantStarter/Tracking/.venv/bin/python -m pip install -r DigiPhantStarter/Tracking/requirements.txt
DigiPhantStarter/Tracking/.venv/bin/python -m pip check
```
Windows (PowerShell):
```powershell
py -3.14 -m venv .\DigiPhantStarter\Tracking\.venv
& .\DigiPhantStarter\Tracking\.venv\Scripts\python.exe -m pip install -r .\DigiPhantStarter\Tracking\requirements.txt
```
Unity launches Python from exactly this path, so don't put the environment anywhere else.

### 3.5 Download the face and gesture models
The pose model ships with the starter. The other two models come from Google's MediaPipe model store, and
the scripts verify them after download.
```sh
DigiPhantStarter/Tracking/.venv/bin/python tools/fruit_tracking/setup_face_model.py
DigiPhantStarter/Tracking/.venv/bin/python tools/hand_tracking/setup_gesture_model.py
```

### 3.6 (Optional) Skybox
The scene uses **Above Day A** from the Unity Asset Store package *AllSky – 220 Sky Skybox Set*.
Aurora purchased this package for use in the examination project. Purchase and examination use alone
do not establish permission to redistribute the original skybox assets in a public Git repository.
Include those source assets only if the applicable licence or the publisher explicitly permits that sharing;
otherwise use the options below. See the [Unity Asset Store EULA](https://unity.com/legal/as-terms).
- **If you own it:** import the package, then run **DigiPhant → Environment → Use Above Day A Skybox**.
- **Otherwise:** run **DigiPhant → Environment → Use Original Solid Background**.

Everything else works without it.

### 3.7 Open in Unity
1. In Unity Hub, choose **Add → Add project from disk**, select the repository folder, and open it with
   **6000.6.3f1**. The first import takes several minutes.
2. Open `Assets/DigiPhant/Scenes/DigiPhant.unity`.
3. **Check the Console for errors.** One-time setup scripts may log lines that start with `DIGIPHANT_`; that is
   expected. Pink objects or red errors mean something is missing (see §7).

## 4. Quick check without a camera

1. Press **Play**. The left panel shows **Test sliders**.
2. Move the sliders. The legs, head, trunk, ears and tail should move.
3. In the collapsible fruit panel on the right, try the debug buttons. They need no camera and no people:

| Button | Expected result |
|---|---|
| Debug: move to feeding bush, then Debug: rear onto hind feet, then Pick apple / Pick banana | The elephant rears up and picks the fruit with its trunk |
| Debug: move to wood | The elephant stands with its trunk in reach of the log; grabbing itself needs P3's fists |
| Debug: sit on log | The elephant sits on the log, then stands up after 1.2 s |
| Debug: drink (drinking panel) | The elephant drinks and sprays water |

## 5. Running a performance

Follow steps 1–6 in order. Red boxes in each screenshot mark the button or area to look at.

| 1. Press Play | 2. Choose the modes | 3. Start the camera | 4. Assign roles |
|---|---|---|---|
| ![Press Play](docs/images/01-press-play.jpg) | ![Choose modes](docs/images/02-choose-modes.jpg) | ![Start the camera](docs/images/03-camera.jpg) | ![Assign roles](docs/images/04-assign-roles.jpg) |
| Press **Play** in the Unity toolbar. The scene opens in **Test sliders** mode, with no camera yet. | Choose group size **3**. Turn on **Seated / upper body**, **Facial** and **Hands**. Keep **Fixed zones** on, so each person owns one strip (P1 = left in the preview). | Click **Camera**. The button shows *Camera · starting…*. Allow camera access if macOS asks; the request may name Unity or Python. Wait for the three-strip preview. | Each person stands **inside their own strip** with head and shoulders visible, then click **Assign roles (open mouth → raise hands)**. Stay in your strip for the rest of the session. |

| 5. Claim the roles | 6. Hold a neutral pose |
|---|---|
| ![Claim the roles](docs/images/05-claim-roles.jpg) | ![Neutral pose](docs/images/06-neutral-pose.jpg) |
| **Only P2** opens the mouth wide and holds about 0.6 s to claim Face; the panel shows *Detecting P2 · %*. Then **only P3** raises both hands above the head for about 0.6 s to claim Hands. P1 becomes Upper body. **Cancel** stops the claim. | Calibration starts automatically once roles are set. Everyone holds a relaxed pose, hands at a comfortable middle height, for **10 s**; P2 also keeps a neutral face for about 2 s. If the countdown doesn't start, click **Set neutral pose (10 seconds)**. The elephant can't walk until this is done. |

> **Redo steps 4–6 every time you press Play.** Roles and the neutral pose are not saved, and changing the
> group size, body mode or Fixed zones clears both. **Reassign roles** reruns step 5, **Clear roles** drops
> them, **Reassign people** re-detects who stands in which strip, and **Set neutral pose (10 seconds)**
> recalibrates.

## 6. Controls

Only one action runs at a time: while the elephant is picking, drinking, carrying or sitting, other actions
wait. "Left" and "right" always mean the performer's own body, not the side of the preview image (the preview
is unmirrored, so your right eye appears on the left of the screen).

### Performance walkthrough

| **P1 raises the left hand** above neutral: the elephant walks forward. Lower it below neutral to walk back. | **P1 tilts the shoulders** left or right: the elephant turns, and its head and tail follow. | Steer into the **blue portal ring** in front of the feeding bush. It is visible only in Play mode. | The portal moves the elephant straight to the picking spot, facing the hanging apple and banana. |

| 11. P2 rears up | 12. P2 picks the banana | 13. P2 picks the apple | 14. P2 comes down |
|---|---|---|---|

| **P2 opens the mouth**: the elephant rears onto its hind feet and reaches for the feeding bush. | While reared up, **P2 winks the left eye** (right eye open): the trunk picks the banana. | While reared up, **P2 winks the right eye** (left eye open): the trunk picks the apple. Closing both eyes is ignored. Open both eyes before the next wink. | **P2 closes the mouth**: the elephant lowers back onto four feet and keeps the picked fruit. |

| 15. P1 drinks | 16. P3 carries the log | 17. P3 shows ✌️ | 18. The elephant sits |

| At the water pool, **P1 holds both hands up for 2 s**: the elephant drinks and sprays water, and walking and legs are locked while it drinks. Lower both hands to re-arm. | Near the log, **P3 makes a left fist** (head lowers, trunk reaches out), **then closes the right fist too**: the elephant grabs the log and carries it while P1 keeps walking. **Open either hand** to put it down. | With the log lying still on the ground, **P3 shows ✌️** with either hand for about 0.3 s: the elephant walks to the log, turns and backs up. Lower the ✌️ before the next one. | The elephant sits on the log, stands up after 1.2 s and returns to idle. If the walk-over gets stuck, it moves straight onto the log. |

### Other controls (no screenshot)

| Who | Movement | Elephant |
|---|---|---|
| P1 | Raise the **left or right hand** | Lifts the matching legs |
| P1 | **Right hand** height | Trunk curl |
| P1 | **Hands apart or together** | Ears open or close |
| P3 | **Left fist** alone | Head lowers and the trunk reaches out, without grabbing |

The elephant can't rear up or pick fruit while it carries the log. The sit refuses only when the log isn't
lying flat, is still rolling, or another action is running.

## 7. Troubleshooting

| Symptom | What to do |
|---|---|
| "Camera setup needed: follow DigiPhantStarter/README.md section 3" | `.venv` or `pose_landmarker_full.task` is missing. Redo steps 3.2 and 3.4 |
| Black or no preview | macOS: **System Settings → Privacy & Security → Camera**, allow Unity or Python. Close other apps using the camera, then click **Retry** in the preview |
| A person shows red `empty` | Move into the middle of your strip, with your head and shoulders visible |
| Winks are missed | Light the face from the front, move closer, wink firmly and hold the other eye open. The fruit panel shows the live wink scores |
| ✌️ does nothing | Is the log on the ground and not rolling? Is Hands on and P3 assigned? Look for `SIT_…` lines in the Console. Hand recognition is logged every second in `Logs/hand_tracking_diagnostics.log` |
| Trees are pink | The neon shader failed on your GPU. Run **DigiPhant → Environment → Use Original Trees** |
| Ports already in use | Only one Unity Play session and one tracker can run at a time. Stop Play, quit any standalone tracker (Q), and try again |

Ports (all localhost UDP):
- 5055: body data
- 5056: commands from Unity
- 5057: preview
- 5058: face actions
- 5059: hand gestures

## 8. Known limitations

- Tested only on one Apple Silicon Mac. The Windows paths exist but haven't been run.
- **Three-person real-camera test passed:** All three performers were tracked simultaneously using one laptop webcam, successfully assigned their roles, and controlled the elephant in Unity. The tested interactions included walking, fruit picking, grabbing and carrying the log, sitting on the log, and drinking. The hand recognizer's recovery issue was resolved, and its recovery was verified during testing.
- The tracker launches automatically **only in the Unity Editor**. A built player needs the tracker started
  by hand.
- The course has no colliders, apart from the stage floor the log rests on. The elephant can walk through
  scenery.

## 9. Instructions for an AI agent setting this project up

You are installing an existing Unity project, not creating one.

1. **Follow §3 in order.** Run commands from the repository root.
2. **Python:**
   - Use only `DigiPhantStarter/Tracking/.venv`. Never install packages globally.
   - Never copy another machine's `.venv`.
3. **Don't modify these files:**
   - `DigiPhantStarter/Tracking/bridge.py`. Its SHA is checked. All tracking changes go in `tools/`.
   - The starter clone in general. Don't push to it.
4. **Don't overwrite tracked files** in `Assets/DigiPhant` or `Assets/StudentWork` with reference copies from
   the starter. The tracked versions are adapted.
5. **Camera:** don't open the webcam during setup. To test the tracker, use the unit tests:
   ```sh
   DigiPhantStarter/Tracking/.venv/bin/python -m unittest discover -s tools/fruit_tracking -p 'test_*.py'
   DigiPhantStarter/Tracking/.venv/bin/python -m unittest discover -s tools/hand_tracking -p 'test_*.py'
   ```
6. **Scene setup:** it is already saved in `Assets/DigiPhant/Scenes/DigiPhant.unity`, so no manual
   wiring is needed. Editor scripts under `Assets/StudentWork/*/Editor` re-apply their part once per machine
   (`[InitializeOnLoad]` plus an EditorPrefs key) and log a `DIGIPHANT_…` line. Each one has a menu under
   **DigiPhant/** to redo or undo it.
7. **Verify after opening Unity:**
   - The Console shows no compile errors.
   - The scene contains `DigiPhant Controls` with `FruitInteraction`, `DigiPhantHandGrab`,
     `DrinkingInteraction` and `ElephantSitOnLog`, and the `Timber` object.
   - The §4 debug buttons work in Play mode.
8. **Report back** your actual OS, Unity, Python and package versions, plus any step you skipped or that
   failed.
